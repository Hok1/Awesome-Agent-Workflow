# rbs-cli token gen --expires-in · 测试设计（轻量）

## 1. 范围与策略

最小充分验证集：覆盖 A1–A4 四条验收标准与契约变更项 `--expires-in`；
测试层级按仓库实情采用 CLI 集成测试（`tools` 现有测试组织为准）。

## 2. 用例集

##### TC1

- 优先级：P0
- 覆盖：A1 / `--expires-in`
- 首次可验证阶段：
- 前置：测试用 SM2/RSA 私钥 PEM 可用
- 输入：`token gen --expires-in 3600`（记录执行时刻 T0）
- 预期：命令成功，输出 JWT 的 `exp` ∈ [T0+3598, T0+3602]
- 断言：解析输出 JWT 的 payload，`exp` 落在区间；比较对象为 JWT payload 数值

##### TC2

- 优先级：P0
- 覆盖：A2 / `--expires-in` 与 `--exp` 互斥
- 首次可验证阶段：
- 前置：无
- 输入：`token gen --exp 9999999999 --expires-in 3600`
- 预期：退出码 2，stderr 提示两参数冲突
- 断言：退出码为 2 且错误输出指明冲突参数；不产生输出令牌

##### TC3

- 优先级：P1
- 覆盖：A3
- 首次可验证阶段：
- 前置：无
- 输入：`token gen --expires-in 0`
- 预期：命令失败，错误文案与既有 exp 校验一致（exp 必须晚于当前时间）
- 断言：错误消息与既有 exp 校验文案一致；退出码非 0

##### TC4

- 优先级：P1
- 覆盖：A4（回归）
- 首次可验证阶段：
- 前置：无
- 输入：`token gen --exp <未来时间戳>`（不带 `--expires-in`）
- 预期：输出 JWT 的 `exp` 等于给定时间戳
- 断言：payload `exp` 与输入一致；既有字段不缺

## 3. 覆盖矩阵

| 验收标准/契约项 | 优先级 | 覆盖用例 | 覆盖状态 | 首次可验证阶段 | 未覆盖原因 |
|---|---|---|---|---|---|
| A1 相对过期正确 | P0 | TC1 | 已覆盖 |  | — |
| A2 互斥拒绝 | P0 | TC2 | 已覆盖 |  | — |
| A4 既有 --exp 回归 | P1 | TC4 | 已覆盖 |  | — |
| 契约变更 `--expires-in` | P0 | TC1、TC2 | 已覆盖 |  | — |

## 4. 缺口与回流

无。
