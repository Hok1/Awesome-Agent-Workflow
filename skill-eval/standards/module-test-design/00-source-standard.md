# 模块测试用例设计质量测评标准 —— RBS 国密 SM2 / rbs-core（SR-1，严格模式）

> 版本：v1.0（2026-09-14）
> 用途：作为 skill-eval 测评平台对 `module-test-design` skill 打分的输入标准。
> 立场：module-design-gate 与测试实现者的下游视角。不问"用例写没写"，只问
> "这份测试设计能不能直接指导实现、并通过门禁的验证闭环审查"。

## 0. 被测评需求是什么

- **SR 编号**：SR-1（RBS 国密 SM2 需求链路的第六个测评点）
- **需求原文**：
  1. SR编号：SR-1
  2. 需求人：目前SM2算法没有应用在此代码仓。需要用户认证支持SM2算法、验证 GTA 签发的 SM2 attestation token、rbs-cli 生成 SM2 token。
- **代码仓**：`globaltrustauthority-rbs`（分支 `master`，基线 commit `7ef62cd`）
- **目标模块**：`rbs-core`
- **交付物**：`.sdd/SR-1/{AR}/{模块组名}/模块测试用例设计.md`（yaml required output）

**这项任务的业务实质**：测试设计是 SDD 链路里「设计→实现」之间的验证闭环闸口。
它的产物不是测试代码，而是**可执行的验证意图**：每条用例必须让实现者不必再问
"前置是什么、输入是什么、怎么算过"。反面典型有三种：用例大全（枚举测试类型而非
覆盖设计风险）、不可执行概要（"补充单测""覆盖异常场景"）、替设计补设计（发明
TOBE 没定义的错误码/字段语义）。本 skill 的规则几乎全部针对这三种。

**本次输入是真实链路产物**：TOBE 说明书与详细设计上下文均采用上一测评点
（module-tobe-design，实验 `95b8f3c3`）`current` 组的真实产出——含 D 编号决策表、
契约清单、风险专题与可测试性输入。链路数据完全同源。

**可测性**：无 MCP、无强制用户交互（`需前置确认` 为合规标记路径）。
硬契约：`##### TCn` 条目形态、四行为字段、「用例正文不得使用任何表格」、
覆盖矩阵五列、说明书不得回写（sha1 钉死）、断言语言无关。

**判据保密纪律**：断言脚本不进 workspace、task 不复述 skill 规则。

## 1. 打分总则

1. **判据全部确定性。** 单条 `command` grader（weight=100），workspace 外执行。
2. **0-100 分锚点**：全过 100，任一失败 0。
3. **一次有效测评即够。** 不取方差；no_skill 组仅作参考（本模型语料含 AAW，
   不构成「无 skill 基线」）。
4. **诚实记录局限。** 断言能判「形态与纪律」，判不了「用例选得是否聪明」
   （最小充分的"充分"需要设计判断，属 llm_rubric 领域，本次刻意不覆盖）。

---

## 2. 硬性门槛（对应断言条款）

| # | 断言 | 出处 |
|---|---|---|
| 0 | TOBE 说明书 sha1 不变（f409b788…） | 成果物协作规则「不得把测试用例写回 TOBE 正式说明书」 |
| 1 | `.sdd/SR-1/AR-1/rbs-core/模块测试用例设计.md` 存在 | yaml output required |
| 2 | ≥3 条 `##### TCn` 用例条目 | §4「每个用例一个条目（##### TCn）」；少于 3 条不构成本需求的最小验证集 |
| 3 | 用例正文（TC 条目内）无表格 | §4 明文「用例正文不得使用任何表格」 |
| 4 | 每条 TC 含 前置/输入/预期/断言 四字段 | §3「至少包含」+ §4 四行为字段 |
| 5 | 覆盖矩阵章节存在、为表格、引用 TC 与 D 编号 | §4 覆盖矩阵五列定义 |
| 6 | 用例正文无可直接粘贴的断言/测试代码 | 质量标准「断言条件精确但保持语言无关，没有输出可直接粘贴的断言代码」 |
| 7 | 含用例总览（树状概览）且声明「最小充分」 | §4「用例总览」+「测试范围与策略摘要」 |
