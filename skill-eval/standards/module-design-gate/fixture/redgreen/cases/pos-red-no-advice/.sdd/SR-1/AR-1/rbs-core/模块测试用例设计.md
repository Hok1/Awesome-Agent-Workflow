# AR-1-SM2用户认证-rbs-core模块测试用例设计

> 本文档是 `rbs-core` 模块在 SR-1 / AR-1（SM2 用户认证）下的独立测试设计成果物，基于同目录正式《模块详细设计说明书.md》与 `.context/详细设计上下文.md` 中的 TOBE 设计与可测试性输入生成。只输出最小充分验证集、覆盖矩阵与缺口，不替 TOBE 补设计，不拆分 AICoding 任务。

## 1. 测试范围与策略

| 项目         | 内容                                        |
|------------|-------------------------------------------|
| 目标模块       | rbs-core（`rbs/core/`）                     |
| 输入正式说明书    | `.sdd/SR-1/AR-1/rbs-core/模块详细设计说明书.md`     |
| 输入 context | `.sdd/SR-1/AR-1/rbs-core/.context/详细设计上下文.md` |
| 变更类型       | 混合变更（既有认证/登记链路改造 + 全仓缺失的 SM2 算法能力新增）       |
| 测试设计状态     | 完成（含 5 项缺口，其中 2 项为上游待确认；核心单侧验证不受阻）          |
| 策略摘要       | 采用最小充分验证集：围绕 D1–D7 决策、K1–K7 契约与 R1–R8，优先 P0/P1 设计风险；按「单元测试 / 模块内功能集成测试 / 契约测试 / 兼容回归测试」四个本次能支撑的层级分层。允许一条用例通过多组等价输入覆盖多个目标（如算法分派、claims 校验、登记推导均以参数集合并）。 |
| 阻塞或待补设计摘要  | ① GTA 侧 SM2 外部表示法待前置确认（context A19 / D5），影响真实生产者互操作契约用例，不阻断本模块单侧验证；② SM2 正/反向测试向量的生成方式待实现期确定（openssl crate 无高层 SM2 签名封装）；③ 登记落库端到端缺既有 DB 测试底座，需新建 harness。 |

**纯新增场景说明**：SM2 能力在全仓零命中（context A1），既有测试无 SM2/EC 用例。新增用例沿用相邻测试组织与惯例：源码文件内联 `#[cfg(test)] mod tests`（如 `authn/common.rs`、`authn/bearer_token.rs`、`authn/token.rs`、`authn/jwks.rs`、`admin/key.rs`、`admin/manager.rs`）；`StubKeyProvider` 风格的 `UserKeyProvider` 假实现；测试密钥/令牌以 `std::env::temp_dir()` 临时文件配合 `Once` 初始化（`authn/token.rs`、`authn/authenticator.rs`）；DB 相关集成沿用 `sqlite::memory:`/文件 SQLite + `execute_sql_file_path` 迁移模式（`rbs/core/tests/db_policy_client_tests.rs`）。不新增测试框架。

## 2. 用例总览

**正常路径（主链路闭环）**
- TC1：原始 header 预解析取 `alg`/`kid`（SM2 与既有算法）
- TC4：`verify_sm2_jws` 对标准 SM2（SM3+默认 Z）`r||s` 签名验签通过
- TC7：JWK `kty=EC,crv=SM2` 解析为可用的 SM2 SPKI PEM
- TC9：SM2 曲线 PEM 推导算法为 `SM2`
- TC10：JWK `crv=SM2` → PEM → 反推 `auth_alg=SM2` 完整推导链
- TC12：登记材料提取（PEM 优先 / JWK 兜底）产出 `(auth_value=PEM, auth_alg=SM2)`
- TC13：Bearer SM2 令牌完整验签返回 `BearerContext`
- TC17：Attest 直连 SM2 PEM 构造成功并验签通过
- TC18：Attest JWKS EC/SM2 按 `kid` 选中键并验签通过
- TC21：SM2 公钥登记落库，再以该用户令牌闭环验签

**失败路径与异常收敛**
- TC5：`verify_sm2_jws` 错误输入统一归一 `TokenInvalid`
- TC6：仅接受 SM2（Z 值）语义签名，非 SM2 语义签名被拒
- TC8：JWKS EC 非 SM2 曲线与缺失/非法字段被拒
- TC11：登记校验不支持曲线/缺字段/超限材料返回 `InvalidParameter`
- TC14：Bearer SM2 分支 claims（iss/aud/sub/exp/nbf）失败语义
- TC19：Attest 选键失败与非法键材料归一 401
- TC20：Attest 构造期快速失败语义（缺键源/非法 PEM/JWKS）

**边界与健壮性**
- TC2：`peek_raw_header` 非法输入统一拒绝且不 panic
- TC3：算法常量契约（`SM2_ALG` / `SUPPORTED_ALGORITHMS` / `SUPPORTED_ALGORITHMS_STR`）

**线格式与互操作契约**
- TC22：JWK JSON 字段名与可选 `y` 的契约
- TC23：JWS `alg` 串与 `r||s` 64 字节签名编码边界

**兼容/回归**
- TC24：既有 PS*/EdDSA 验签行为不变、未知算法仍拒
- TC25：既有 JWKS RSA/OKP 行为不变、EC 非 SM2 错误语义更新
- TC26：既有 RSA/EC(P-256/384/521) 登记行为不变
- TC27：不新增配置字段、不新增密码学依赖、无 DDL 变更

**幂等与安全**
- TC15：取键失败掩码与算法-密钥一致（防用户枚举/alg 混淆）
- TC16：同一 SM2 令牌重复验签幂等

## 3. 最小充分测试用例集

### 3.1 单元测试

#### 3.1.1 原始 header 预解析与算法分派（K1 / D2）

##### TC1 预解析紧凑 JWT header 取 alg 与 kid

- 优先级：P0
- 覆盖目标：K1 / D2 / R1
- 场景：对 3 段紧凑 JWT 的第 1 段做原始 base64url 预解析，取出 `alg` 与可选 `kid`，不进入 `jsonwebtoken::Algorithm` 枚举、不发起验签。
- 建议位置：`rbs/core/src/auth/authn/common.rs` 内联 `#[cfg(test)] mod tests`（与既有 `test_validate_algorithm_*` 相邻）
- 自动化：Rust 单元测试（`cargo test`），可合并为一个表驱动用例
- 前置：无外部依赖；仅需构造 `base64url(header) + "." + base64url(payload) + "." + signature` 形态的紧凑串（header 段可控即可）
- 输入：参数集合：(a) header `{"alg":"SM2","kid":"k1","typ":"JWT"}`；(b) header `{"alg":"SM2"}`（无 `kid`）；(c) header `{"alg":"PS256"}`
- 预期：三次解析均成功，返回 `RawJwsHeader`
- 断言：`alg` 分别为 `SM2` / `SM2` / `PS256`；`kid` 分别为 `Some("k1")` / `None` / `None`；解析过程不产生验签副作用

##### TC2 预解析对非法输入统一拒绝且不 panic

- 优先级：P0
- 覆盖目标：K1 / R6
- 场景：header 段损坏或结构非法时，统一归一为 `AuthError::TokenInvalid`，不 panic。
- 建议位置：同 TC1
- 自动化：Rust 单元测试（表驱动）
- 前置：无
- 输入：参数集合：(a) 段数 ≠ 3（2 段、4 段、空串）；(b) header 段含 base64url 非法字符；(c) header 段解出非 JSON（如 `abc`）；(d) header JSON 缺 `alg`；(e) `alg` 为数字或对象（非字符串）
- 预期：全部返回错误，且进程不 panic
- 断言：错误变体为 `TokenInvalid`；无 panic

#### 3.1.2 算法白名单与常量契约（K1 / R6）

##### TC3 算法常量契约与 SM2 不并入既有枚举

- 优先级：P0
- 覆盖目标：K1 / D2 / R6
- 场景：SM2 作为独立分派常量存在，但不被加入 `jsonwebtoken` 可解码算法列表；对外展示串纳入 SM2。
- 建议位置：`rbs/core/src/auth/authn/common.rs` 内联测试（同步更新既有 `test_supported_algorithms_constant`）
- 自动化：Rust 单元测试
- 前置：无
- 输入：读取 `SM2_ALG`、`SUPPORTED_ALGORITHMS`、`SUPPORTED_ALGORITHMS_STR`
- 预期：`SM2_ALG` 等于 `"SM2"`；`SUPPORTED_ALGORITHMS` 仍恰为 `[PS256, PS384, PS512, EdDSA]`（长度 4，不含 SM2）；`SUPPORTED_ALGORITHMS_STR` 同时含四个既有算法串与 `SM2`
- 断言：三项取值的元素集合与上述一致

#### 3.1.3 SM2 验签核心（K2 / K3 / D1）

##### TC4 verify_sm2_jws 标准 SM2 签名验签通过

- 优先级：P0
- 覆盖目标：K2 / K3 / D1 / R1 / R5
- 场景：对给定 signing input，用 SM2（SM3 摘要 + 标准默认 Z）产生的 64 字节 `r||s` 签名与对应 SM2 公钥 PEM，验签成功。
- 建议位置：新增 `rbs/core/src/auth/authn/sm2.rs` 内联 `#[cfg(test)] mod tests`（`authn/mod.rs` 注册 `pub mod sm2;`）
- 自动化：Rust 单元测试
- 前置：SM2 测试密钥对与签名向量，来源须与生产验签同底座（OpenSSL 3.x / SM3 / 默认 Z）：可由测试内 OpenSSL 生成，或使用外部参考实现检入的固定向量（见 GAP3）
- 输入：signing_input = `base64url(header) + "." + base64url(payload)` 的 ASCII 字节；signature = 64 字节 `r||s`；public_key_pem = 对应 SM2 公钥
- 预期：返回 `Ok(())`
- 断言：结果为 `Ok`；不产生副作用

##### TC5 verify_sm2_jws 错误输入统一归一 TokenInvalid

- 优先级：P0
- 覆盖目标：K2 / K3 / D3 / 安全（算法-密钥一致）
- 场景：跨算法公钥、篡改签名/输入、空材料等错误一律归一为 `TokenInvalid`，不放行。
- 建议位置：`rbs/core/src/auth/authn/sm2.rs` 内联测试
- 自动化：Rust 单元测试（表驱动）
- 前置：TC4 的 SM2 向量；一组非 SM2 公钥 PEM（RSA、Ed25519、P-256）
- 输入：参数集合：(a) SM2 签名 + RSA/Ed25519/P-256 公钥 PEM；(b) 篡改签名中 1 字节；(c) 篡改 signing_input（变更 payload，SM3 摘要不一致）；(d) 空签名或空公钥
- 预期：全部返回错误
- 断言：错误变体为 `TokenInvalid`；无 panic；无"验签通过"结果

##### TC6 仅接受 SM2 用户标识（Z）语义

- 优先级：P0
- 覆盖目标：K3 / 安全（Z 值语义）/ R5
- 场景：必须使用 SM2 语义（含默认用户标识 Z）验签；非 SM2 语义（普通 ECDSA-with-SM3，无/错误 Z）产生的签名必须失败。
- 建议位置：`rbs/core/src/auth/authn/sm2.rs` 内联测试
- 自动化：Rust 单元测试（负向向量构造见前置；若无法自动构造则改为参考向量或人工验证，通过标准为"非 Z 语义签名被拒"）
- 前置：一组使用标准默认 Z 的签名（正向）；一组使用普通 ECDSA-with-SM3（无 Z）的签名（负向，见 GAP3）
- 输入：正向向量、负向向量分别送入 `verify_sm2_jws`
- 预期：正向通过；负向被拒
- 断言：正向返回 `Ok`；负向返回 `TokenInvalid`（即使用普通 EC 通用验签无法替代 SM2 语义）

#### 3.1.4 JWKS EC/SM2 解析（K5）

##### TC7 JWK kty=EC,crv=SM2 解析为可用 SM2 PEM

- 优先级：P0
- 覆盖目标：K5 / K3 / D2 / R2
- 场景：由 `x`/`y`（各 32 字节）组装的 SM2 公钥经 `jwk_to_pem` 输出 SPKI PEM，可被 OpenSSL 识别为 SM2 曲线并可用于验签。
- 建议位置：`rbs/core/src/auth/authn/jwks.rs` 内联测试（与既有 `test_unsupported_key_type_ec` 相邻）
- 自动化：Rust 单元测试
- 前置：SM2 公钥仿射坐标 `x`/`y`（各 32 字节，base64url 无填充）；TC4 的签名向量
- 输入：JWK JSON `{"kty":"EC","crv":"SM2","x":"<b64url>","y":"<b64url>"}`
- 预期：返回非空 PEM
- 断言：PEM 可被 OpenSSL 解析；公钥曲线为 SM2（OID `1.2.156.10197.1.301`）；用该 PEM 可成功验证 TC4 向量

##### TC8 JWK EC 非 SM2 与缺失/非法字段被拒

- 优先级：P1
- 覆盖目标：K5 / R6
- 场景：仅 `crv=SM2` 的 EC 键被接受，其余 EC 曲线与缺字段/非法编码被拒，错误语义走 EC 曲线分支。
- 建议位置：`rbs/core/src/auth/authn/jwks.rs` 内联测试
- 自动化：Rust 单元测试（表驱动）
- 前置：无
- 输入：参数集合：(a) `kty=EC,crv=P-256,x,y`；(b) `kty=EC,crv=SM2` 缺 `y`；(c) 缺 `x`；(d) `x`/`y` 非合法 base64url；(e) `kty=EC` 缺 `crv`
- 预期：全部返回错误
- 断言：错误变体为 `TokenInvalid`；(a) 错误文案为 EC 曲线不支持语义（不再为 "unsupported key type"）

#### 3.1.5 公钥登记校验与 JWK→PEM 推导（K6 / D4）

##### TC9 SM2 曲线 PEM 推导算法为 SM2

- 优先级：P0
- 覆盖目标：K6 / D4 / R3
- 场景：`validate_and_derive_alg` 对 SM2 曲线公钥 PEM 稳定推导为 `SM2`。
- 建议位置：`rbs/core/src/admin/key.rs` 内联测试（与既有推导用例相邻）
- 自动化：Rust 单元测试
- 前置：SM2 公钥 PEM（与 TC7 同源）
- 输入：SM2 SPKI PEM
- 预期：返回 `Ok("SM2")`
- 断言：算法串等于 `SM2`

##### TC10 JWK crv=SM2 → PEM → 反推 auth_alg 完整推导链

- 优先级：P0
- 覆盖目标：K6 / K5 / D4 / R3（关键映射规则：auth_alg 由 PEM 反推）
- 场景：JWK `crv=SM2` 先经 `jwk_ec_to_pem` 转 PEM，再由 PEM 反推 `auth_alg`，链路贯通。
- 建议位置：`rbs/core/src/admin/key.rs` 内联测试
- 自动化：Rust 单元测试
- 前置：SM2 `x`/`y` 坐标
- 输入：JWK JSON `{"kty":"EC","crv":"SM2","x":"<b64url>","y":"<b64url>"}`
- 预期：`jwk_ec_to_pem` 产出 SPKI PEM；`validate_and_derive_alg(该 PEM)` 返回 `SM2`
- 断言：PEM 非空且可解析为 SM2 公钥；反推算法串等于 `SM2`

##### TC11 登记校验不支持曲线/缺字段/超限材料返回 InvalidParameter

- 优先级：P1
- 覆盖目标：K6 / R6 / R7
- 场景：不支持曲线与非法/超限材料被拒，错误类型与文案符合契约。
- 建议位置：`rbs/core/src/admin/key.rs` 内联测试
- 自动化：Rust 单元测试（表驱动）
- 前置：无
- 输入：参数集合：(a) `jwk_ec_to_pem` 输入 `crv=P-256` 或其他非 SM2 `crv`；(b) 缺 `crv`/`x`/`y`；(c) `x`/`y` base64url 非法；(d) `validate_and_derive_alg` 输入非 SM2 曲线 PEM；(e) PEM/JWK 串长度 > 10240 字节
- 预期：全部返回 `RbsError::InvalidParameter`
- 断言：错误变体为 `InvalidParameter`；(a)(d) 文案含 `Unsupported`；(e) 文案含 `exceeds maximum size`

##### TC12 登记材料提取 PEM 优先、JWK 兜底

- 优先级：P0
- 覆盖目标：K6 / D4 / R3 / R8
- 场景：`extract_auth_material` 将 SM2 材料规范为 `(auth_value=PEM, auth_alg=SM2)`，且 PEM 优先于 JWK。
- 建议位置：`rbs/core/src/admin/manager.rs` 内联测试（与既有 `extract_auth_material_*` 相邻）
- 自动化：Rust 单元测试（表驱动）
- 前置：SM2 公钥 PEM 与等价 JWK
- 输入：参数集合：(a) 仅 `public_key=SM2 PEM`；(b) 仅 `jwk=crv SM2`；(c) 同时提供 `public_key`（SM2 PEM）与 `jwk`（另一材料）
- 预期：返回 `(auth_value, auth_alg)`
- 断言：(a) `auth_value` 等于输入 PEM、`auth_alg` 等于 `SM2`；(b) `auth_value` 为等价 SM2 PEM、`auth_alg` 等于 `SM2`；(c) 采用 PEM 分支

### 3.2 模块内功能集成测试

#### 3.2.1 BearerToken SM2 验签（K2 / K4 / D3）

##### TC13 Bearer SM2 令牌完整验签返回 BearerContext

- 优先级：P0
- 覆盖目标：K2 / K4 / D3 / R1
- 场景：`BearerTokenVerifier::verify` 在 `alg=SM2` 时经"预解析 sub → 取用户 SM2 公钥 → SM2 验签 → claims 复校"返回 `BearerContext`。
- 建议位置：`rbs/core/src/auth/authn/bearer_token.rs` 内联测试（复用 `StubKeyProvider` 风格，注入返回 SM2 公钥的假 provider）
- 自动化：`tokio` 测试（`#[tokio::test]`）
- 前置：`StubKeyProvider` 返回对应用户 SM2 公钥 PEM；合法 `alg=SM2` 令牌，含 `sub`/`iss`（= config.issuer）/`aud`（= config.audience）/`exp`（未过期）/`role`
- 输入：令牌紧凑串
- 预期：返回 `Ok(BearerContext)`
- 断言：`ctx.sub` / `ctx.iss` / `ctx.role` 等于令牌声明；`ctx.token_type` 为 `Bearer`；`ctx.claims` 保留原始 claims

##### TC14 Bearer SM2 分支 claims 校验语义

- 优先级：P0
- 覆盖目标：K4 / R7
- 场景：SM2 分支 claims 校验与既有 `Validation` 等价，覆盖必填集合、issuer/audience 与时间容差。
- 建议位置：`rbs/core/src/auth/authn/bearer_token.rs` 内联测试
- 自动化：`tokio` 测试（表驱动，签名有效、claims 可变）
- 前置：TC13 的 key provider 与 SM2 签名能力
- 输入：参数集合：(a) `iss` 不符；(b) `aud` 不符；(c) 缺 `sub`（预解析失败）；(d) 缺 `iss`；(e) `exp` 已过期；(f) `nbf` 在未来
- 预期：(e) 过期语义；(f) 未生效语义；(a)(b)(c)(d) 通用无效令牌语义
- 断言：(e) 错误变体为 `TokenExpired`；(f) 为 `TokenNotYetValid`；(a)(b)(c)(d) 为 `TokenInvalid`；均不返回 `BearerContext`

##### TC15 取键失败掩码与算法-密钥一致

- 优先级：P0
- 覆盖目标：K4 / K2 / D3 / 安全（防用户枚举、防 alg 混淆）
- 场景：用户不存在、跨算法公钥均不被放行，且对外不泄露用户是否存在。
- 建议位置：`rbs/core/src/auth/authn/bearer_token.rs` 内联测试
- 自动化：`tokio` 测试（表驱动）
- 前置：多种 key provider 行为（返回 Err / 返回非 SM2 公钥）
