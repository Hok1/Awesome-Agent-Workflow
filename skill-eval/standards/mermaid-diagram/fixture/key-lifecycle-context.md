# 用户 SM2 密钥生命周期 —— 业务事实清单（SR-1 补充设计输入）

> 本文档是设计补充的输入材料，只列业务事实与约束，不规定表达方式。

## 来源

- SR-1 原始需求：`.sdd/SR-1/original-requirement.md`

## 事实

1. **生成**：用户 SM2 密钥对由用户在本地经 rbs-cli 生成，私钥以 PEM 文件留在用户侧，
   不进入 RBS 服务。
2. **登记与启用**：管理员通过 RBS 管理接口把用户 SM2 公钥（PEM）登记到用户库；
   登记完成即密钥启用，用户可用私钥签名 token 访问受保护接口。
3. **轮换**：到达轮换周期或安全策略要求时，用户生成新密钥对并请求管理员登记新公钥；
   新公钥启用后旧公钥失效，旧密钥签发的 token 不再被接受。
4. **泄露处置**：私钥疑似暴露时，用户报告管理员，管理员立即吊销该公钥登记；
   自吊销时刻起，该密钥签发的 token 一律拒绝（含吊销前签发但未过期的）。
5. **吊销**：管理员移除/失效公钥登记。吊销是处置状态，不是终点。
6. **销毁**：吊销后的密钥材料由用户侧安全擦除，生命周期结束。
7. **失败约束**：泄露的密钥不得回到可用状态；吊销不可逆。
8. **参与方**：用户（操作 rbs-cli）、RBS 管理员（操作管理接口）、RBS 服务（验签与用户库）。
